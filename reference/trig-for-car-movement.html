Reference · Trigonometry for the car

Trig for car movement

The compressed version of Lesson 01. Use it when predicting a position, debugging a direction, or wiring the same components into sensors.

The 30-second version

Sine is the sideways percentage

sin θ = opposite / hypotenuse. In the car's triangle, the opposite leg is the horizontal one. Sine tells you what fraction of the speed goes left or right.

Cosine is the up percentage

cos θ = adjacent / hypotenuse. The adjacent leg is the vertical one because θ is measured from the nose, not from the x axis. Cosine tells you what fraction goes up or down.

Movement, one frame Δx = −sin(θ) · speed    // left is negative x
Δy = −cos(θ) · speed    // up is negative y

x += Δx
y += Δy

In car.js this is written as this.x -= Math.sin(this.angle) * this.speed and this.y -= Math.cos(this.angle) * this.speed. Subtracting a positive component and adding a negative one are the same operation.

The one-sentence model

Sine gives the sideways share; cosine gives the up share; the canvas subtracts both because left is negative x and up is negative y.

Conventions in this project

Sign conventions
Thing Convention What it means
Car angle θ Radians, 0 = up, positive = left Left arrow adds 0.03 rad per frame; right subtracts.

Screen y Increases downward Upward movement has negative Δy.

The velocity triangle

270° 3π/2 ≈ 4.712 −1 0 (+1, 0) Right
360° 2π ≈ 6.283 0 1 (0, −1) Up again

Multiply the Δ column by the speed. At speed 2, double both components. At negative speed, both components flip. The minus signs in the formulas are fixed; the results are not: Δx is negative only while the nose points left, and Δy only while it points up. At 120°, Δx is negative but Δy is positive. Sine always scales the sideways component; cosine always the forward one.

Conversions radians = degrees × π / 180
degrees = radians × 180 / π
0.03 rad ≈ 1.72°   ·   full turn = 2π ≈ 6.283 rad

Code patterns

Move the car

// car.js — one frame of movement
this.x -= Math.sin(this.angle) * this.speed;
this.y -= Math.cos(this.angle) * this.speed;

Draw the car at its angle

ctx.save();
ctx.translate(this.x, this.y);
ctx.rotate(-this.angle);   // canvas + is clockwise; car + is CCW
ctx.beginPath();
ctx.rect(-this.width / 2, -this.height / 2, this.width, this.height);
ctx.fill();
ctx.restore();

The car shape is drawn with its nose along −y. At angle 0, no rotation is needed. As the angle grows, rotate(−θ) turns the shape counterclockwise, matching the direction of movement.

Steer, including reverse

// car.js — steering
const flip = this.speed > 0 ? 1 : -1;
if (this.controls.left)  this.angle += 0.03 * flip;
if (this.controls.right) this.angle -= 0.03 * flip;

flip is not trigonometry. When the car reverses, the rear of the car leads, so the body rotates the opposite way for the same steering input. The sign flip models that. If you remove it, the car will steer like a forklift instead of a car.

Turn a direction back into an angle

// Point the nose at a target (useful for sensors and steering)
const dx = target.x - this.x;
const dy = target.y - this.y;
this.angle = Math.atan2(-dx, -dy);

The heading vector is (−sin θ, −cos θ). To invert it, solve sin θ = −dx and cos θ = −dy, then use atan2(sin, cos). The two minus signs are the same screen convention, read backward.

Convert degrees for the math library

const radians = degrees * Math.PI / 180;
const dx = -Math.sin(radians) * speed;
const dy = -Math.cos(radians) * speed;

Math.sin and Math.cos always take radians. The car's own angle is already in radians, so no conversion is needed inside car.js.

Debug checklist

  • Car moves down at angle 0. The y sign is flipped. Up is negative y; use y -= cos θ · speed.
  • Car turns right when you press left. The angle sign is flipped. Positive angle is a left turn; the left arrow should add.
  • Car turns the wrong way only in reverse. The flip is missing or inverted.
  • Car points one way but moves another. The draw rotation and the movement formula disagree. Check rotate(−θ).
  • Car moves sideways at 90° and nowhere else. That is correct: cos 90° = 0, so there is no vertical component.
  • Car does not move at 90°. It should move left at full speed. Check that x uses speed · sin θ, not speed · cos θ.
  • Car jumps after many turns. The angle is unbounded, but sine and cosine are periodic, so the direction should not jump. Check for a separate normalization bug.
  • Car moves the wrong way after setting a negative speed. A negative speed flips both components along the heading. That is reverse, not a trig error.
