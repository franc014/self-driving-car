Road geometry, lanes, and lerp

The compressed version of Lesson 03. Use it when a lane is off by half its width, when a border needs to become a segment, or when the camera makes a world coordinate look wrong.

The one-sentence model

The road is an interval [left, right]; every lane boundary is a fraction i / laneCount across it; every lane center is half a lane further in.

01The road interval

Constructor left = x − width / 2
right = x + width / 2
width = right − left

World coordinates. The road object stores world x values. The camera translation in main.js happens at draw time and does not modify the road.

02Lane boundaries and centers

The two placements laneWidth = width / laneCount

boundaryi = left + i · laneWidth    = lerp(left, right, i / laneCount)
centeri    = left + (i + 0.5) · laneWidth = lerp(left, right, (i + 0.5) / laneCount)

centeri = boundaryi + laneWidth / 2

i runs from 0 to laneCount for boundaries. For centers, valid indices are 0 to laneCount − 1.

Reverse lookup: which lane contains x?

Not in road.js yet; useful for lane detection t = (x − left) / (right − left)
laneIndex = clamp(floor(t · laneCount), 0, laneCount − 1)
center of that lane = lerp(left, right, (laneIndex + 0.5) / laneCount)

03Linear interpolation

util.js lerp(A, B, t) = A + (B − A) · t
              = (1 − t) · A + t · B

t = 0  → A
t = 1  → B
t = 0.5 → midpoint
t < 0 or t > 1 → extrapolation
lerp(20, 380, t)
t Result Feature on the 3-lane road
0 20 Left border
1/6 80 Lane 0 center
1/3 140 Divider 1
1/2 200 Lane 1 center
2/3 260 Divider 2
5/6 320 Lane 2 center
1 380 Right border

The weighted-average form is the intuition: at t = 0.25, the result is 75% of A and 25% of B. The weights always sum to 1. See Wikipedia's linear interpolation article.

lerp on two coordinates

A point fraction t along a segment P.x = lerp(A.x, B.x, t)
P.y = lerp(A.y, B.y, t)

Use the same t for both coordinates. A sensor ray and a border are both segments; the intersection is the pair of t values that produce the same point. That is the next mathematical step after this reference: Radu's segment intersection lesson.

05Borders and practical infinity

The border data structure
Level Type Meaning
borders Array of segments Every edge of the drivable surface
border Two points One edge, from start to end
border[0] {x, y} Start point
border[1] {x, y} End point

top = −1000000 and bottom = +1000000 keep the road far longer than any viewport. Use a large finite number rather than Infinity: infinities propagate through subtraction and intersection formulas and turn into NaN.

Commands that use the borders:

  • road.borders[0] is the left edge; road.borders[1] is the right edge.
  • border[0] is the top point; border[1] is the bottom point in this build.
  • Drawing only needs the two endpoints; intersection needs the same two endpoints plus a ray.

06Camera: world to screen

main.js translate(0, −car.y + 0.7 · canvas.height)

screenY = worldY − car.y + 0.7 · canvas.height
screenX = worldX    (no horizontal translation in this build)

At car.y = 200 and canvas.height = 800, the translation is −200 + 560 = 360. The car's screen y is 200 + 360 = 560. If the car moves to y = 150, the translation becomes 410 and the car's screen y is still 560.

  • World coordinates: stored by the road and car; unbounded.
  • Screen coordinates: pixels after the camera translation; y grows down.
  • Camera transform: a draw-time translation, not a property of the road.

07Canvas state checklist

  • ctx.setLineDash([20, 20]) persists until changed.
  • ctx.setLineDash([]) restores solid strokes.
  • ctx.lineWidth and ctx.strokeStyle persist across paths.
  • Setting canvas.width or canvas.height clears the bitmap and resets the context, including transform and styles.
  • ctx.save() and ctx.restore() isolate the camera transform.
  • Draw order controls layering: road first, car second.

References: MDN setLineDash, MDN HTMLCanvasElement.height, and MDN canvas transformations.

08Pitfalls

What goes wrong and which fraction fixes it
Symptom Likely cause Check

Road is twice as wide Treating width as half-width left = x − width / 2
Borders come out dashed Dash pattern not reset setLineDash([]) before borders
Lane centers move but edges do not width mutated after construction left/right are snapshots
Road scrolls off screen Camera translation missing or inverted −car.y + 0.7 × height

Ask two questions before editing

Is this an edge or a middle? Is this number a world coordinate or a screen coordinate? Almost every road bug is one of those two confusions.
